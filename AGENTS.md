# Инструкции для AI-агента

## 1. Описание проекта
Проект представляет собой REST API для обработки платежей онлайн-школы.

Разрабатывается в рамках тестового задания на позицию Junior Python/FastAPI Developer в компании Квитто.

Оригинальное техническое задание находится в папке technical_task/.

Техническое задание является основным источником требований. Не добавляй функциональность, которая не предусмотрена заданием или не запрошена разработчиком.

## 2. Технологический стек
 - Python 3.11+
 - FastAPI
 - Pydantic v2
 - SQLite
 - SQLAlchemy 2.0 (синхронная работа)
 - pytest + httpx

Не добавляй дополнительные библиотеки, фреймворки и инфраструктуру без согласования.

## 3. Архитектура проекта
Используется простая слоистая архитектура (Layered Architecture) с разделением ответственности (Separation of Concerns).

Структура проекта:

```
app/
├── core/       # Подключение к БД и конфигурация
├── models/     # ORM-модели SQLAlchemy
├── schemas/    # Pydantic-схемы запросов и ответов
├── routers/    # Эндпоинты FastAPI
├── services/   # Бизнес-логика
└── main.py     # Точка входа приложения
```

Ответственность компонентов:

- Routers — обработка HTTP-запросов и формирование ответов.
- Schemas — валидация входящих данных и сериализация ответов.
- Models — описание таблиц базы данных.
- Services — бизнес-логика приложения.
- Core — подключение к базе данных и общая конфигурация.

Не усложняй архитектуру без необходимости. Избегай лишних абстракций, дополнительных слоёв и ненужных паттернов проектирования.

## 4. Правила разработки
- Соблюдай глобальные инструкции пользователя.
- Реализуй только запрошенную функциональность.
- Работай поэтапно: одна логическая задача за раз.
- Используй аннотации типов Python.
- Пиши простой, читаемый и поддерживаемый код.
- Для денежных расчётов используй только целые числа в копейках. Не используй float.
- Используй синхронные сессии SQLAlchemy.
- Придерживайся стандартных подходов FastAPI и SQLAlchemy.
- Не добавляй Docker, Alembic, авторизацию и другую необязательную инфраструктуру без запроса.
- Покрывай важную бизнес-логику и поведение API тестами.
- Не изменяй файлы, не относящиеся к текущей задаче.
- Значимые архитектурные решения предварительно согласовывай с разработчиком.


## 5. Работа с техническим заданием

- Перед реализацией функциональности изучай соответствующий раздел технического задания.
- Не придумывай требования, которых нет в задании.
- Если требование неоднозначно, сообщи об этом и предложи варианты решения.
- Приоритет — корректная работа API, точность денежных расчётов и соблюдение бизнес-правил.
- Не реализуй бонусные задания без отдельного запроса.

## 6. Проверка результата

После выполнения задачи:

- Кратко перечисли изменённые файлы.
- Объясни, что было реализовано.
- Выполни подходящие проверки или тесты.
- Сообщи о найденных ошибках и ограничениях.
- Не переходи к следующей задаче без запроса.
